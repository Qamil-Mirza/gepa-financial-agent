# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added
- Drop-in SDK: `pitstop.wrap`, `workflow`, `agent`, `tool` (block/steer/halt guard), `prompt` (versioned, developer edits win), `Halted` and `BudgetExceeded`.
- Hard dollar budget ledger with atomic reserve/settle, and per-workflow `budget_usd`; PitStop's own model calls go through it (`docs/config.example.toml`).
- `pitstop status`, `pitstop drifts` and `pitstop budget` commands, and a keyless quickstart example (`examples/quickstart`).
- Open-source repo basics: Apache-2.0 license, Contributor Covenant code of conduct, security policy, issue and pull-request templates, changelog and a CI workflow.
- Ruff linting (pyflakes rules) and offline-by-default test suite.
- `pitstop budget reconcile [--older-than-min 60] [--release]` lists old budget reservations, left open by a process that died mid-call or by a call still running; `--release` frees them and lists what it freed.
- `pitstop.workflow` and `pitstop.agent` decorate generator and async-generator functions; the run spans the generator's steps and never leaks to the consuming code.
- `wrap` meters `chat.completions.parse` and `with_raw_response` / `with_streaming_response` calls (on the client or the resource). Raw responses are settled from their parsed usage; streaming responses and raw streams, which PitStop can't read, are charged their full reservation (`usage_estimated: "worst_case"`).
- An endpoint that rejects PitStop's injected `stream_options` with a 400 is retried once without it, and later stream calls to that base_url skip the injection.
- `wrap` meters the chat stream helper (`chat.completions.stream`), the Responses API (`responses.create` / `parse` / `stream`) and legacy `completions.create`, sync and async. A stream helper reserves when called, settles when its manager exits, and releases its reservation if it is never entered. A background Responses call (`background=True`, or a result still `queued` / `in_progress`) is charged its full reservation. Assistants, Realtime, Batch and `client.beta.*` are not metered yet (Anthropic's `beta.messages` is, see below).
- `wrap` supports the Anthropic SDK (`Anthropic` / `AsyncAnthropic`, install `pitstop[anthropic]`): `messages.create` (and `stream=True`), `messages.parse`, `messages.stream` (with `text_stream`, `get_final_message()` and `get_final_text()`), the same under `beta.messages`, `beta.messages.tool_runner` (each of the runner's model calls is metered), and raw / streaming responses; `messages.batches` is not metered. Cache writes are charged at their write premium (1.25x input for 5-minute writes, 2x for 1-hour writes and for writes without a breakdown), a `stop_reason` of `"refusal"` counts as a refusal for L0, and an unpriced `claude-*` model (or Bedrock-style `…anthropic.claude-*` id) falls back to a conservative $15 / $75 per million tokens (`known=False`).
- L1 pre-action gate: a `side_effects=True` tool on a `high` or `medium` workflow is checked by a judge model (prompt `l1_gate_v2`, `watch` meter) before it runs; a rejection is a P0 `out_of_scope_action` drift and blocks the call. The tool's arguments and the agent's recent calls reach the judge inside `<tool_args>` and `<recent_calls>` blocks that the prompt treats as data, with any `</` inside written as `<\/` so the text cannot close its block (`l1_gate_v1` stays in the package, unchanged). Configure the judge in `[judge]` (`model`, `base_url`, `api_key_env`, `timeout_s`; defaults to `openai/gpt-oss-120b` on Crusoe via `CRUSOE_API_KEY`), or pass your own client with `pitstop.init(judge_client=..., judge_model=...)`. In `[judge]`, an unknown key, or a `base_url` that is not an `http://` or `https://` URL with a host, is a config error. When the judge is missing or cannot decide, `pitstop.workflow(on_gate_error=...)` decides: `high` blocks, `medium` runs by default. Verdicts are `gate` events, failures `gate_error` events.
- `pitstop.workflow(...)` rejects an invalid `criticality`, `sensitivity`, `fix_mode` or `on_gate_error` with a `ValueError` when the workflow is defined.
- Fallback action: `pitstop.workflow(..., fallback_model="...")` pins a model. A P1 `tool_call_breakage` or `refusal_spike` in a run whose model changed within the last 24 hours (runs redirected to the pinned model don't count as a change) engages it: later agent-meter calls of the workflow go to the pinned model (`llm_call` events carry `fallback_from`, `"(unset)"` when the call named no model), the drift's action is `fallback` and a `fallback` event is recorded. A `base_url`-only change records the drift and alerts but does not engage the fallback. It stays on until `pitstop fallback clear <workflow>`; `pitstop fallback status` lists active fallbacks, and `pitstop drifts` shows a cleared one's action as `fallback (cleared)`.
- Alerts: P0 and P1 drifts are sent right away to PagerDuty (Events v2), Opsgenie, Slack (incoming webhook), SMTP email or a generic webhook, routed by urgency (`[alerts.routes]`; defaults P0 -> PagerDuty, Opsgenie, Slack, webhook and P1 -> Slack, email, webhook) from a background thread that never blocks the agent and finishes before the process exits. Each open drift alerts once per channel, again when it escalates from P1 to P0. P0/P1 sends that fail with a network error, a 5xx or a 429 are retried twice with a short backoff; over SMTP only a network error, a dropped connection or a 4xx reply is retried (bad credentials, a 5xx greeting or any other SMTP error is not). A send left pending by a killed process stops blocking after 2 minutes, and the next send for that drift and channel marks it `superseded`. A P0 whose drift could not be written to the store still pages its P0 channels (not deduplicated; its `alerts` rows have no drift id). The alert's "what likely changed" line skips runs that went to the pinned fallback model, whether or not the fallback is still on. P2/P3 drifts go in a daily digest (`pitstop alerts digest [--force]`). Every alert says what drifted, what likely changed and what PitStop did. `pitstop alerts test [--channel NAME]` checks each channel. Secrets come only from env vars named in `[alerts.<channel>]`; inline secrets are rejected.
- Budgets refuse new runs once they are used up: entering `pitstop.workflow(...)` raises `BudgetExceeded` when the workflow's own budget, a global budget without `base_url`, or the global budget for the endpoint of the workflow's previous run is already spent. The run is recorded with the new status `refused` and a P0 `budget_exhausted` drift. A store error during this check is logged and the run starts. `Ledger.exhausted(...)` returns the first used-up budget.
- Spend-spike P0: a run whose settled agent spend passes 10x / 5x / 3x (sensitivity low / normal / high) its workflow's baseline (the median agent spend of the last 20 `ok` runs, at least 10 needed, floored at $0.01) records a P0 `spend_spike` drift with action `halt` on any criticality, and its next wrapped call raises `Halted` (`pitstop.detect.spend`).
- `finresearch run --offline [--no-inject-drift]`: the research-swarm example with no keys and no network (scripted worker model, canned research answers, scripted gate judge, in `finresearch.offline`). PitStop's pre-action gate blocks the scenario's injected GeForce gaming research calls; `pitstop drifts` then lists one P0 `out_of_scope_action` drift with action `block`. Without the injection the run records no drift.
- `wrap` follow-ups: a Responses call with `previous_response_id` or `conversation` adds 32,000 tokens to its prompt estimate for the earlier turns it is billed for (`PRIOR_CONTEXT_TOKENS`); a legacy `completions.create` prompt of token ids counts as that many tokens; Responses custom tool calls (`input` as the arguments) and hosted tool calls (`web_search_call`, `file_search_call`, `code_interpreter_call`, `computer_call`, `mcp_call`, `image_generation_call`, `local_shell_call`; arguments `""`) are recorded as tool calls and never count as parse failures; a Responses `refusal` content part makes the call refused.
- Verdicts as span events: with OpenTelemetry installed (`pitstop[otel]`), every drift PitStop records adds a `pitstop.verdict` event to the current span, with `pitstop.drift_type`, `pitstop.level`, `pitstop.action`, `pitstop.run_id`, `pitstop.reason` (at most 300 chars) and `pitstop.drift_id`. Best effort; a no-op without opentelemetry or a recording span.
- `pitstop.otel.SpanProcessor` (`pitstop[otel]`): add it to an OpenTelemetry tracer provider and each trace becomes a PitStop run (`otel-<trace id>`, adapter `otel`). It reads GenAI spans in the current and older GenAI semantic-convention names, OpenInference and OpenLLMetry into `llm_call` (with a price-table cost estimate), `tool_call` / `tool_result` and `agent` events linked by span ids, runs the L0 checks on them and records drifts observe-only (action `record`; P0/P1 still alert). Each drift adds a `pitstop.verdict` event to the trace's root span; its `pitstop.reason` can carry up to 300 characters of tool arguments to your tracing backend. The workflow name is the root's `pitstop.workflow` attribute, else `SpanProcessor(workflow=...)`, else the root span's name. Spans inside a `pitstop.workflow(...)` run are skipped, costs never reach the budget ledger, and the processor never raises into the traced app. `import pitstop` still works without opentelemetry installed.
- `pitstop.sdk.guard`: the tool guard behind `@pitstop.tool` (`guard_call` / `aguard_call`, `record_tool_result`, `tool_args_text`), shared with the framework adapters. A tool call is guarded once: a `@pitstop.tool` called inside an already guarded call of the same tool name only runs and records its result.

### Changed
- A drift whose action is `halt` (`budget_exhausted`, `spend_spike`) sets the run's pending halt on every criticality, not only on high-criticality workflows: a run that catches a `BudgetExceeded` from one call gets `Halted` from its next call.
- The research-swarm example is watched by the PitStop SDK: `Swarm.run_all()` runs inside `pitstop.workflow("financial-research", criticality="medium", tools=("youcom_research",))`, each worker inside `pitstop.agent(agent_id, goal=directive)`, and the paid You.com call is a `@pitstop.tool(side_effects=True, name="youcom_research")` that the L1 gate judges against the agent's directive. A blocked call reaches the worker as an ERROR event naming the reason, and its next plan is told about it; a `pitstop.Halted` ends the swarm, which prints the reason and records the run as halted (`meta.json` gains a `pitstop` entry with the run id). The hackathon per-step supervisor is now opt-in: `Swarm(supervisor=None)` is the default, and `finresearch run --legacy-supervisor [PROMPT]` turns it on (default prompt `supervisor_v0.txt`; this replaces `--prompt`). `--model`, `--shadow-prompt`, `--halt-on-drift` and `--correct-on-drift` need `--legacy-supervisor`. `Swarm(watch=False)` skips the PitStop wiring (research is called directly); the benchmarks and the demo pair use it to measure the legacy supervisor alone.
- The research swarm (orchestrator, agents, You.com client, per-step supervisor, timeline, the demo page and the old run viewer, with their prompts and scenarios) moved out of the `pitstop` package into `examples/financial-research/`, a uv workspace member (package `finresearch`, distribution `pitstop-financial-research`). Its commands moved with it: `pitstop check`, `run`, `compare`, `timeline`, `serve` and `demo` are now `finresearch check`, `run`, `compare`, `timeline`, `serve` and `demo`, with the same flags. The `pitstop` wheel and CLI now carry only the SDK. `pitstop.config` keeps the package paths and `pitstop_home()`; `Settings` and `load_settings()` are now in `finresearch.config`. The `jaccard` helper L0 uses is now `pitstop.detect.text.jaccard`.
- `pitstop` is now an installable `src/` layout package with packaged assets.
- The GEPA engine lives in `pitstop.correct`; the evaluator is supplied by the caller.
- Eval sets and detector calibration tooling are collected under `benchmarks/`.
- Hackathon-era docs moved to `docs/history/`.
- Runs and the You.com cache now default to `~/.pitstop/runs` and `~/.pitstop/cache/youcom` (override with `PITSTOP_HOME`, `PITSTOP_RUNS_DIR`, `PITSTOP_CACHE_DIR`); previously they lived under `pitstop/pitstop/runs` and `pitstop/pitstop/cache` in the checkout.
- `pitstop` is now an installed console script (previously `python -m pitstop.cli` run from `pitstop/pitstop/`).
- Store schema v5 (v4 adds the `alerts` table; v5 adds `runs.scanned_at`, `runs.fallback_from`, `events.span_id`, `events.parent_span_id`, the `l2_state` table and indexes on `runs(workflow, started_at)`, `runs(scanned_at, ended_at)` and `ledger(run_id)`): older DBs are upgraded step by step in one transaction, and a DB written by a newer PitStop fails closed with `Halted("pitstop config invalid: ...")`.
- A `with_streaming_response` call is charged its full reservation when its manager is entered, not when the call returns: a manager that is never entered (or whose request fails) releases its reservation, like a stream helper's.
- `llm_call` events carry `prompt_tokens`, `completion_tokens` (the settled or estimated counts) and `refused`. A run whose agent calls went to the pinned fallback model records the model it replaced in `runs.fallback_from`. A run's `adapter` tag set before its first wrapped call is kept.
- Drift records count every occurrence (`occurrences`, `last_seen`) and keep only the newest 20 evidence entries, each `{"run_id", "ts", "detail"}`; `pitstop drifts` shows the occurrence count (`occurrences` column) and the real first and last seen times.
- `runs.base_url` is stored normalized (no trailing `/`), matching the budget ledger.
- Drift detection and the run's model tag use only calls on the `agent` meter; judge, supervisor and GEPA calls no longer trigger L0 drifts. `llm_call` events carry their `meter`.
- Per-agent tool history and per-run LLM history keep the newest 64 calls; refusals are counted over the whole run.
- The steer limit (2 per run) holds when several threads share a run, and its `Halted` carries the id of the drift that tripped it.
- `pitstop.meter()` exited in another `contextvars.Context` than the one it entered restores the meter instead of raising `ValueError`.
- An async-generator workflow abandoned inside a reference cycle ends its run once, with its cleanup inside the run, instead of racing a second close ("asynchronous generator is already running").
- The alert sender's worker threads close their store connection after each alert.
- `pitstop.sdk.wrap` is a package; wrapped streams pass `isinstance` checks against the SDK's stream classes.
- A pending P0 halt on a high-criticality workflow is recorded as a `halt` event (`pending: true`) when it is set.
- Drift actions escalate on dedup in the order record < fallback < steer < block < halt.
- With no judge configured (no `CRUSOE_API_KEY`, no `[judge]` key, no `judge_client`), `side_effects=True` tools on `high` workflows are now blocked by the pre-action gate's failure policy; set `on_gate_error="allow"` on the workflow to run them anyway. The offline quickstart uses a scripted judge.

### Removed
- The superseded supervisor stack, dead scaffold and committed generated data.
